# Observed callback discovery

This tool adds one observed indirect-call root to a copy of a discovered function
map. It creates metadata for the existing PS2Recomp producer; it does not emit an
address-specific runtime adapter or mark the game playable.

Inputs stay local: the user's ELF, original body map, labeled native failure log,
numeric Ghidra boundary report, producer configuration, and independently recorded
SHA-256 pins. Keep every generated game unit outside the public checkout.

Run `CallbackBoundaryReport.java` in an existing Ghidra project with analysis
disabled and read-only project mode. Its arguments are the root address and a
bounded exclusive window end, in hexadecimal. It emits addresses and counts,
never disassembly. Read-only Ghidra changes are discarded.

The current gate accepts only a contiguous leaf containing supported instructions,
one register return and its delay slot, no external direct flow, no existing owner
overlap, and disagreement-free ELF/Ghidra classification. Other control-flow shapes
require a new reviewed gate. A return pattern by itself is insufficient.

Create a pins JSON with exactly `elf`, `ranges`, `observed_log`, `boundary_report`,
and `base_config`, each containing its previously recorded SHA-256 string. Then:

```text
python observed_roots.py --elf <local-elf> --ranges <body-map.json> --log <native-log> --report <numeric-ghidra-log> --config <producer.toml> --pins <pins.json> --output <new-private-directory>
ps2_recomp <new-private-directory>/config.toml
python -B -m unittest discover -s research/discovery -p test_observed_roots.py
```

The output preserves all original discontiguous body ranges, adds the reviewed
root, and supplies original entries to the producer. Global registration is
regenerated by PS2Recomp's existing function-table emitter. Unmapped static JAL
targets and executable-segment padding are not promoted to functions.

Generation/annotation identity, source compilation, link closure, controlled
instruction effects, and live original-game comparison are separate checks.
Promotion stays blocked until all required checks pass, including real Debug and
Release boot probes and baseline-preservation hashes. See
[the current candidate evidence](../../docs/OBSERVED_DISCOVERY_CANDIDATE.md).
